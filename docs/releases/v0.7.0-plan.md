# v0.7.0 — Search, prepare, apply

Status: implemented and validated for v0.7.0: 172 automated checks, 29/29 isolated browser scenarios and GitHub CI passed. See v0.7.0.md for evidence and actual coverage; Lever sending remains experimental and was not verified against a real employer.

## 1. Saved automatic searches

- Enter a role and/or company, optional location and work mode. No employer-board URLs or API keys required for the integrated public feeds.
- Start with Remotive (remote jobs; public listings delayed by 24 hours) and Arbeitnow (primarily European/German jobs). Display attribution, source links and coverage; do not claim whole-market coverage.
- Save, edit, pause and resume searches; choose a supported 6, 12 or 24 hour interval. Shared persistent provider caches prevent multiple searches from multiplying upstream requests.
- Preserve new/reviewed, archived and favorite decisions; deduplicate repeat arrivals and preserve jobs on incomplete/failed reads.
- Show last attempt, next attempt, recoverable errors and matches. Closing the browser does not stop the local service; sleeping or stopping the machine does.

Acceptance: fictional feeds exercise scheduled discovery, filters, cache/restart behavior, deduplication, errors and workspace isolation. Browser checks cover search creation/editing and results in ES/EN and mobile.

## 2. Automatic preparation

- Opt in per search to prepare matching jobs; also allow preparing an individual saved job.
- Select relevant confirmed profile facts, render an immutable CV draft and create/link the tracked application. Explain selected evidence and missing information.
- Use only approved facts and answers. No paid AI or invented qualifications. Missing profile details produce an actionable review item.
- Repeated processing is idempotent; preserve existing user choices and submitted/uncertain applications. Review and approval remain explicit before transmission.

Acceptance: no unapproved facts, clear behavior with missing data, repeat processing and profile changes; generated drafts can be reviewed in the existing PDF flow.

## 3. Supported automatic submission

- Extend the existing visible Lever runner for a narrow supported form shape, including the current approved PDF.
- Separate permission to fill from permission to submit. Bind a one-use authorization to the exact application, destination and approved materials.
- Complete a supported application after authorization; stop for missing answers, unknown required fields, authentication, CAPTCHA or additional legal decisions.
- Record a verified confirmation only when evidence supports it. Uncertain results require reconciliation and cannot be blindly retried.
- Keep manual handoff available for other portals and unsupported forms. Development tests never submit to real employers.

Acceptance: synthetic forms prove success, consent, duplicate prevention, stale-material rejection, unsupported fields and uncertain outcomes, while retaining the manual flow.

## Integration and release

Put search at the start of the navigation and onboarding; expose prepared applications and clear next steps. Preserve bilingual, keyboard and mobile usability. Backups and exports include new data while restored automation is paused.

Run isolated end-to-end and relevant automated tests, review the combined changes, align versions and user documentation, validate CI, then publish main + annotated v0.7.0 tag + GitHub release. Keep the repository private. Report actual coverage and any incomplete acceptance criteria instead of marking a partial delivery complete.
