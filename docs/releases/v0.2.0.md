# v0.2.0 — Local reliability and recovery

## Delivered

- **Recoverable backups:** a consistent PostgreSQL snapshot, generated PDFs, per-file hashes and an authenticated manifest. Backups are reopened and verified before success is reported. A separate key file is required for restoration.
- **Isolated restore:** creates a new database and data folder, restores and checks documents and row counts, issues fresh sign-in credentials, and disables job sources and saved searches until reviewed again. Existing databases and folders are never overwritten.
- **Simpler setup:** separate database and credentials for each new installation, resumable `.env.pending`, clearer bilingual diagnostics, a corrected macOS launcher, and explicit configuration selection for restored workspaces in another checkout.
- **More reliable discovery:** streamed response limits, validated fields and regions, complete Lever description sections, readable Greenhouse descriptions, and visible partial-result notices.
- **Clearer export:** progress, retryable errors, and a verified JSON download. The privacy page explains the backup and recovery route in English and Spanish. A macOS backup launcher is included.

## Supported scope and limits

This release is verified on **macOS with Node 24 and Homebrew PostgreSQL 17**. Fresh installations were exercised in isolated copies on that same computer; a second physical machine, Windows, Linux, a cold dependency download, and the Docker startup path were not validated end to end. Docker support remains available with that limitation documented.

Backups contain **unencrypted personal data**. Store them in a private or encrypted location and retain the key file separately. JSON exports are for portability; operational recovery uses the verified backup archive.

AI processing, employer-site autofill/submission, email access, interview coaching and hosted multiuser accounts remain outside v0.2. The original product specification includes future work beyond this release. No open-source license has been selected.

## Start and update

See [English quick start](../../README.md), [inicio en español](../../README.es.md), [backup and restore](../operations/backup-restore.md), [local setup](../operations/local-setup.md), and [source validation](../operations/source-validation.md).

Existing installations retain their database and keys. To update a checkout after preserving a backup:

```sh
pnpm run stop
git pull --ff-only
pnpm install --frozen-lockfile
pnpm start
```
