## Migration, export and restore

Migration 0009 is additive. The isolated upgrade test applies 0000–0008, inserts a legacy search, job decision, source and match, then verifies IDs and values survive 0009. Legacy searches retain matcher version 1 and their old provider set; related results remain off.

Restore coverage includes pending and completed runs, provider state, materialized results, reviews, identity memberships, historical decisions and automatic preparation. Restoring pauses searches and preparation, cancels unfinished runs and sources, clears ownership/leases, preserves completed statuses, and leaves the source database unchanged. Export includes personal search history but excludes query caches and cancels unfinished work in the portable copy.

Run locally with a loopback maintenance database using `CAREER_BACKUP_TEST_ADMIN_URL` and `CAREER_V080_MIGRATION_ADMIN_URL`, then `pnpm test:integration`. Never point fixtures at an installation database.

## Search results and performance

The SQL integration fixture checks workspace isolation, legacy filters, SKIPPED decisions, review state, strong identity grouping, conflicting historical decisions, optional application metadata and stable non-overlapping pagination.

The performance fixture contains 10,000 synthetic jobs and 20 searches. Thirty measured samples follow a warm-up, with no fixture ANALYZE. The final full search-suite run measured a cold grouped request of 277.3 ms, search-save POST p95 7.9 ms, unread-list p95 158.6 ms, and first-page p95 414.7 ms. The test enforces a 3 s cold-request guard and a 1 s warmed p95 target. This is local loopback evidence, not a capacity claim for other hardware.

An earlier query took 19–43 seconds in un-analyzed fixtures. EXPLAIN exposed repeated scans of identity conflicts. Materialized filtering stages and indexed per-identity conflict lookups removed that repeated work; pagination still precedes application metadata lookup. The final test intentionally does not mask this regression with ANALYZE.

## Browser validation

An intermediate complete run passed 28/31 scenarios and exposed one app defect plus outdated test expectations. First arrivals into an empty search list now render automatically; arrivals into a populated list wait for the explicit update action. Test fixtures select only seeded providers, use current visible controls, and increment their mocked result version. Targeted v0.6.1 review/recovery, v0.7.0 search-to-PDF and v0.7.1 background-arrival scenarios subsequently passed in full.

A subsequent complete run passed 30/31 and reproduced an intermittent review-state overwrite. The job detail now versions reads, invalidates pending reads on mutation/unmount, and clears previous-job content when the route changes. A five-second delayed initial response reproduces the bug deterministically: the POST returns 200 and the database records the review, but the unguarded page returns to unread. A negative control reverted only a disposable dashboard copy and failed at that continuation; the guarded page passed in both languages. This regression is now part of the v0.6.1 scenario.

Final complete suite after this fix: **31/31 passed**, run `c7fb6b4421e6`. The disposable stack completed teardown and process/database/path isolation checks passed. The separate live-row-count observation reported a concurrent change in live jobs; the fixture runner used only its verified disposable database, so this is recorded rather than claiming all live activity was frozen. Final edge suite after the stale-read fix: 10/10 passed, including stale application conflicts, resume preservation, missing records, session outages, pagination and bilingual mobile errors.

The additional v0.8 browser harness passed: real cached backend create → queued run → successful result; mocked slow/partial/error states; preserved context; consent and idempotency; keyboard; Spanish/English including success messages after language changes; 320, 390, 768, 1096 and 1440 px; and 200% text scaling. Live installation fingerprints were unchanged and disposable resources were removed. This harness combines one real local backend flow with explicitly mocked edge states, not live external-provider end-to-end coverage.

## Relevance and limits

The original 144 synthetic cases informed development, including its original 66-case partition labelled holdout; it is not independent evaluation. Six role families have synthetic ranking probes. After freezing matcher rules, 48 new prospective synthetic cases (18 positive, 30 negative) were fixed and passed on their first execution without rule adjustment. They include ES/EN aliases, punctuation-sensitive technologies, seniority, near company names, country restrictions and work modes. None establish real-world relevance or generalization to arbitrary roles.

No new-user study was performed. Text scaling is not a claim of native browser zoom testing across browsers. Windows/Linux CI validates builds, types and domain checks; local browser interaction was checked on macOS Chromium. Source coverage and availability remain provider dependent, and the local service must remain running.
