# v0.3.1 — Profile, resume and draft reliability

## Delivered

- **Resume reuse after preference changes:** copied facts are resolved by their original creation timestamp and exact kind, text, tags and source, within the current workspace. Only currently approved, unchanged copies are reused. Corrections never silently substitute different content into an earlier selection.
- **Editable profile entries:** corrections create a new profile revision and need confirmation before use. Archive and restore actions preserve existing PDFs and their original claims. Concurrent edits are rejected with recovery guidance.
- **Assisted resume selection:** only documents accepted by the current-profile and approved-fact checks are offered. Outdated versions remain in My resumes, with instructions to regenerate and review them.
- **Per-tab drafts:** manual job imports, manual application forms and notes survive route changes and page reloads. Notes are kept separately for each application. Saving clears only the corresponding submitted draft; failed requests retain it. Explicit discard asks for confirmation. Signing out clears session drafts.
- **Job search states:** no matches, no jobs, loading and errors have distinct feedback; late search responses cannot overwrite a newer search.
- **Earlier local UX work included:** clearer bilingual navigation and home guidance, profile sections, work-experience start/end dates, locally rendered PDF preview, improved resume typography and pagination, and removal of the draft footer.

## Use and limits

In **My resumes**, choose **Use as starting point** to generate a new PDF from an earlier selection. Profile changes require a newly reviewed version before assisted preparation. Earlier downloads remain unchanged.

In **My profile**, **Edit** opens the complete saved text, including existing employment dates. Saving a correction marks it for confirmation. **Archive** removes it from the available resume content; **Restore and confirm** makes it available again. Structured editing of legacy employment and education fields is a follow-up, not part of this patch.

Drafts use browser `sessionStorage`, scoped to the installation origin and tab. They are temporary convenience copies, not backups or saved application history. Closing the tab may discard them; explicit sign-out removes them. If storage is unavailable, the app warns and asks for confirmation before ordinary link navigation. Browser history navigation in that exceptional mode is not fully guarded.

No database migration is required for this patch. Existing profile revisions and PDF files remain valid historical records. Use the usual local launcher after updating and installing dependencies. Updating the source does not redesign existing PDF bytes: regenerate them to use the new layout.

Lever assistance retains its existing limits: contact-field autofill, manual upload/review/submission, no automatic employer submission. Public repository preparation remains deferred; the repository is private. This patch does not resolve the previously deferred dependency alerts.
