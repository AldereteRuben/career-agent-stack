# Validación de v0.9.0 — primera tanda

Fecha: 2026-10-04. Rama: `release/v0.9.0`. Base: `be27bcbfd5b69a786aa0bdfcab5f13ba9907fbfa` (v0.8.2).

**Estado: base técnica en desarrollo; no es una versión publicable.** El plan completo está en [v0.9.0-plan.md](v0.9.0-plan.md). La aplicación sigue anunciando v0.8.2 y sus capacidades de IA siguen desactivadas.

## Implementación de esta tanda

- Esquemas estrictos para borradores de búsqueda, análisis de anuncios, propuestas de CV y respuestas de experiencia.
- Autorización vinculada a cuenta, conexión, revisión, operación y categorías efectivamente compartidas. La automatización solo admite análisis de ofertas y búsquedas autorizadas.
- Validación de citas contra el anuncio y de referencias contra la experiencia aprobada incluida en la instantánea. Estos controles comprueban procedencia, no garantizan que una afirmación sea verdadera.
- Preguntas personales o desconocidas requieren respuesta de la persona; el contrato no admite un borrador automático para ellas.
- Textos derivados del CV con procedencia, huellas de las fuentes y aprobación vinculada al texto y PDF exactos. Los documentos anteriores conservan su contrato.
- Reglas puras para reservas, prioridad manual, exclusión por cuenta/workspace y presupuesto diario UTC. **La cola persistente y su reserva atómica todavía no existen**: la comprobación de dominio no adquiere un bloqueo ni consume presupuesto por sí sola.
- Supervisor de procesos con argumentos separados, entrada por stdin, entorno limitado, salida acotada, cancelación y timeout. Los errores públicos no contienen stderr ni argumentos.
- Diagnósticos separados de Codex y Claude Code para consultar capacidades y sesión oficial sin iniciar tareas del modelo. No forman parte de una pantalla de conexión ni de un adaptador productivo.
- Comando `pnpm run test:ai` y pasos de CI para ejecutar fixtures sin cuentas de proveedor.

## Hallazgos corregidos durante la revisión

1. El permiso para un resumen de anuncio no autorizaba explícitamente la experiencia adicional. Ahora se comprueban las categorías de la entrada real.
2. Un cambio en la petición de búsqueda podía reutilizar una clave de caché idéntica. La identidad incluye un hash de todos los datos de entrada.
3. Una respuesta personal podía citar experiencia para parecer válida. La política de respuesta se fija en el servidor y las preguntas personales no admiten borrador.
4. La revisión de textos podía aprobarse sin demostrar que coincidía el PDF mostrado. Ahora se exige la misma huella del PDF y de todos los textos.
5. Los reintentos previos al despacho admitían errores que requerían intervención. Se restringen a fallos transitorios, con límite estricto, y nunca a revocación, cuenta cambiada, cuota agotada o respuesta inválida.
6. Varios hechos válidos individualmente podían exceder el tamaño compuesto de entrada. Se rechazan sin truncarlos.
7. El supervisor podía quedar pendiente por pipes heredados o resolver antes de conocer un error de stdin. Se corrigieron los tiempos de cierre y la normalización de esos fallos.

`pnpm run test:ai` pasó sus 71 casos (51 de dominio/procesos y 20 de diagnósticos). Combinado con `test:unit`, se comprobaron 116 casos únicos; los 32 casos de dominio de IA aparecen en ambos comandos y no se cuentan dos veces. Las pruebas automatizadas de base pasan, mientras que el experimento manual de aislamiento descrito abajo sigue fallando su criterio G0.

`test:ai` utiliza solamente programas de prueba. Los scripts `scripts/ai/*-capability-probe.mjs` son diagnósticos manuales diferentes: consultan la sesión del CLI oficial y no deben añadirse a CI ni ejecutarse como una prueba unitaria.

El experimento manual `scripts/ai/codex-isolation-probe.mjs` ejecuta el CLI real con un proveedor HTTP local ficticio y bloqueo de red externa en macOS. La configuración candidata completó una respuesta ficticia sin cabecera de autenticación y excluyó el canario de instrucciones del proyecto, pero mantuvo la herramienta `request_user_input` y referencias a la carpeta personal dentro del contexto. Por eso **no pasó G0**. No hubo inferencia de proveedor ni consumo de la suscripción; detalles y límites en la decisión 017.

## G0: lo que aún falta resolver

- Codex 0.160.0: lectura de estado y ventanas de uso demostrada en este equipo. Falta probar una ejecución que no herede instrucciones, archivos, herramientas, MCP, skills ni hooks. Una opción de solo lectura y una respuesta JSON no demuestran ese aislamiento.
- Claude Code 2.1.289: diagnóstico de autenticación y controles candidatos documentados. Falta resolver el encaje de la suscripción en esta integración; consulta de alcance enviada al usuario. No se da por autorizada una API con facturación independiente.
- Ambos: pruebas de inferencia real con datos sintéticos, cuentas de prueba autorizadas, límite de consumo y matriz de sistemas operativos; login cancelado/caducado y cambio de cuenta durante una ejecución.
- Windows: el supervisor usa `taskkill /T` para un padre vivo. No garantiza recoger descendientes que sobrevivan a un padre ya terminado; se necesitaría un mecanismo de Job Objects o una restricción de soporte demostrada.
- POSIX: la limpieza alcanza el grupo creado para la tarea. Un descendiente que se separe mediante una sesión distinta queda fuera; el supervisor termina su espera y no señala procesos ajenos. Los adaptadores deberán demostrar que no crean procesos fuera de ese grupo.

Mientras G0 siga abierto, no conectar estos módulos a las acciones del usuario como si la inferencia estuviera disponible. La persistencia, los adaptadores, los flujos ES/EN, backup/restauración, evaluaciones reales y release siguen pendientes. No se aplicaron migraciones, cambiaron credenciales, generaron CV ni enviaron candidaturas sobre los datos reales.
