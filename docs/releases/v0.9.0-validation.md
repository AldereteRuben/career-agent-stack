# Validación de v0.9.0

Fecha: 2026-10-04. Rama: `release/v0.9.0`. Base: v0.8.2 (`be27bcbfd5b69a786aa0bdfcab5f13ba9907fbfa`).

**Este registro recoge la verificación local de la versión.** Durante las pruebas, la instalación real conservó v0.8.2 y no se migró su base de datos. Claude Code está aplazado por decisión del usuario. Se continúa con Codex sin añadir facturación de API independiente.

## Conexión real autorizada

El usuario autorizó **hasta cuatro tareas pequeñas con datos completamente ficticios** usando la sesión actual de Codex. Se ejecutaron exactamente cuatro invocaciones, sin reintentos de la aplicación, mediante `codex-cli 0.160.0` y `gpt-6.1-sol`. Ninguna utilizó el perfil, los CV ni las ofertas guardadas del usuario.

| Tarea | Resultado |
| --- | --- |
| Búsqueda en inglés | Criterios válidos; salario señalado como condición que el motor no puede filtrar |
| Análisis en español | Citas verificadas y coincidencias apoyadas en la experiencia ficticia; instrucción maliciosa del anuncio ignorada |
| Texto de CV en inglés | Reformulación con la métrica original; no añadió idiomas, duración ni disponibilidad no demostrados |
| Respuesta personal en español | Solicitó confirmación de permiso de trabajo; no respondió por la persona |

Las cuatro salidas pasaron el contrato y la comprobación de fuentes. Uso reportado por esas invocaciones: 17 537 tokens de entrada y 803 de salida; no se deduce un coste monetario ni un porcentaje de suscripción. La CLI puede reintentar transporte internamente: una invocación no equivale necesariamente a una única petición HTTP. El límite autorizado de cuatro tareas está agotado.

Estas pruebas comprueban contratos concretos, no la calidad de cualquier respuesta futura. No se probó un nuevo login real ni una cancelación durante inferencia real con la cuenta.

## Aislamiento de Codex

La configuración final de `scripts/ai/codex-isolation-probe.mjs` pasó la prueba nativa con respuestas locales simuladas: cero herramientas anunciadas, cero catálogo personal, sin la ruta personal ni el canario de instrucciones, y sin cabecera de autenticación. El intento de invocar una herramienta no anunciada fue rechazado; no se creó el archivo testigo. La cancelación de un stream ficticio también pasó con el proceso nativo: cerró la conexión y no dejó procesos activos ni zombies. No hubo inferencia ni consumo de suscripción en esas pruebas. No se observaron descendientes en esa ejecución; los descendientes se cubren con procesos sintéticos.

`app-server` se utiliza para cuenta, login y límites, sin abrir una conversación de inferencia. La inferencia usa `exec` con configuración explícita, instrucciones separadas, directorio temporal privado y sin configuración personal. La cuenta y el modo de facturación se comprueban antes y después. Detalles, intentos anteriores y límites: [decisión 017](../decisions/017-codex-feasibility.md).

La ejecución se habilita únicamente para **macOS y Codex 0.160.0**. Linux/Windows conservan las funciones ordinarias; su integración nativa de IA sigue sin certificarse. Un resultado de compilación en esos sistemas no sustituye esta comprobación.

### Navegador

- Recorrido nuevo de IA: producción aislada con **respuestas de proveedor simuladas**, cuatro operaciones, consentimiento exacto, cuenta desconectada/reconexión, errores, cancelación, recuperación, automatización y borrado explícito. Cero conexiones o tareas reales de IA en la BD del fixture. Última evidencia: `output/playwright/v090-4a3f984c7bee` (ignorada por Git).
- CV: recuperar texto editado al volver, bloquear otro idioma/contexto, continuar con originales, guardar sin aprobar automáticamente y conservar edición si falla el guardado.
- ES/EN, foco por teclado y anchos 360, 768, 1096 y 1440 px; 720×450 comprueba geometría equivalente al 200 % sobre 1440×900. No es una prueba real de zoom asistido ni de lector de pantalla. No hubo prueba formativa con usuarios externos.
- Regresión general: la primera pasada cubrió **30 de 32** escenarios. Los dos fallos eran supuestos del harness en producción: navegar antes de que el POST de backup fuera aceptado y exigir la doble lectura de StrictMode. Ambos se corrigieron y se repitieron por separado, **2/2 cada uno** incluyendo acceso inicial. Evidencias: `ccf3e941dffc`, `0453bddf766b`, `9d3a5d1ba0f8`; el último también pasó en desarrollo (`8c9d6d9102d2`). No se presenta como una única ejecución de 32/32.
- La asistencia de envío se prueba contra formularios ficticios. No se envió ninguna candidatura a empresas.

### Casos de integridad cubiertos

La cola comprueba exclusión por cuenta, revocación, prioridad manual, cancelación concurrente, fuentes cambiadas y reservas a través de medianoche UTC. La repetición HTTP tras perder la caché de preview recupera la tarea aceptada. Un permiso automático no autoriza una acción manual. La automatización verifica exactamente idioma y evidencia permitida, evita el histórico y conserva la deduplicación después de borrar resultados.

Las respuestas conservan país/ámbito/caducidad y empiezan sin aprobar; una respuesta IA aprobada deja de ser reutilizable si cambia su evidencia. Las comprobaciones de PDF y vinculación comparten los bloqueos de oferta/perfil para que una edición concurrente no permita usar un documento obsoleto.

Restaurar conserva filas y evidencia, revoca permisos, pausa políticas, cancela/interrumpe tareas y preserva límites/marcadores mínimos. La retención elimina consumo antiguo y tareas sin propuesta o descartadas después de 30 días; conserva pendientes y evidencia vinculada. Borrar manualmente exige preview y vuelve a comprobar las dependencias.

## Cierre

La primera ejecución remota detectó dos diferencias del entorno de pruebas: Windows no expone permisos POSIX `0600`, y el pool PostgreSQL podía resolver su cierre antes de terminar de cerrar los sockets. Las pruebas mantienen las comprobaciones de archivos en Windows, esperan el cierre efectivo antes de eliminar cada base aislada y cubren el orden con tres regresiones sintéticas. Estos ajustes no habilitan la ejecución nativa de IA fuera de macOS.

Versiones, README ES/EN, changelog y guías actualizados a 0.9.0. La instalación limpia terminó correctamente. El resultado remoto del commit publicado puede consultarse en la [Release v0.9.0](https://github.com/AldereteRuben/career-agent-stack/releases/tag/v0.9.0) y sus ejecuciones de CI. La secuencia exigida es CI del commit candidato, main, tag anotado y Release Latest; ningún resultado local sustituye esas comprobaciones remotas.

Los artefactos privados de prueba, registros de login, credenciales y datos locales quedan fuera de Git y de las publicaciones.
