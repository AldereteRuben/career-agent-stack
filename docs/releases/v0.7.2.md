# v0.7.2 Reliable drafts and application history

This patch closes the edge-case review of the search → profile → resume → application journey. It protects work already entered and makes long application histories accessible.

## Changes

- Application updates include the displayed record version. If another tab has changed it, the app reloads the latest record and asks you to review before repeating the change.
- Reusing a saved resume asks before replacing a different draft, including drafts for another job. Cancelling keeps the draft intact; editing the PDF just generated needs no unnecessary replacement prompt.
- Application history has pages of 25 records and search by role or company. Direct links load independently of the current page, including records beyond the previous 500-item limit.
- Rejected, withdrawn and hired applications keep their history without offering preparation actions that the server would reject.
- Temporary session-check errors retain the destination and offer a retry. A genuine authentication rejection still leads to sign-in.
- Search criteria above 200 characters receive an error without truncation; the field keeps its text and receives focus.
- Profile loading discards outdated responses and waits for the authenticated view before landing on a requested section.

## Updating

Use the existing [local update instructions](../operations/local-setup.md). No new dependency, database migration or configuration is required. Restart the local service to load the updated app. The interface remains available in Spanish and English.

## Existing limits

Job sources remain Remotive, Arbeitnow and explicitly followed company boards. Matching and resume selection use deterministic rules. Scheduled work requires the local service to remain running. Supported Lever submissions require explicit authorization for each application; real-employer submission is not verified by these tests. Unsupported forms continue on the original website. Native Windows startup/shutdown and a full Linux/WSL installation are outside this local validation.
