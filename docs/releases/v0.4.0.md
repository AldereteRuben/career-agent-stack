# v0.4.0 — From profile to application

## Delivered

- **Editable employment and education:** role/qualification, employer/school, start and end months, current work/study and description are stored separately. Education descriptions are optional. Corrections still require confirmation. Canonical employment text created by v0.3.1 is recognized without rewriting the stored record; ambiguous older text remains editable as text, with an explicit option to complete structured fields.
- **Connected steps:** Profile → Resume → Application retains the job and application context. After reviewing a PDF, continue directly to its application. The selected resume is persisted, downloadable and selected first for assisted preparation. Repeated continuation uses the open application instead of creating duplicates.
- **Resume selection checks:** the server rejects outdated/unapproved resumes, another job's resume, foreign-workspace records, submitted/closed applications and active assisted attempts. Selection is recorded in application history. Generic resumes remain usable for a job.
- **PDF language and zoom:** select English or Spanish headings and date labels independently of the interface language. User-written descriptions are preserved verbatim. Zoom stays inside the preview; page text is available separately.
- **Manage saved offers:** search title or company, filter favorites/availability, archive and restore, and page through results. Filters and page survive reload through the URL. Late mutation responses reload the current filter.
- **Bilingual guidance:** updated ES/EN screens and startup READMEs describe the next action and manual submission boundaries.

## UX review follow-up

- Profile section shortcuts reduce scrolling. Editing an entry focuses its heading and brings the form below the fixed header; examples help explain what to write.
- Resume preparation keeps the name, language and selected fact IDs per job/application in tab storage. Returning from the profile or reloading restores the preparation. Other jobs retain separate drafts; sign-out clears them. Changed or unconfirmed fact IDs are excluded with visible recovery guidance.
- The selection count shows the 50-item limit, unavailable extra checkboxes are disabled at that limit, and an empty selection explains how to enable generation. Fields are disabled while loading or generating.
- Job detail links retain list search, filters and page for the return action. Pagination shows the total page count. An existing application has one primary action; preparing its resume retains its application context.
- Keyboard search focus is visible, and detailed information about older PDFs is collapsed by default.

## Upgrade and limits

Back up the installation before updating. Install dependencies and restart through the local launcher to apply `0005_structured_profile_and_resume_link`. It adds optional structured entry metadata and an application-document reference with a workspace-scoped foreign key. It does not rewrite earlier PDF files or profile prose.

Existing documents remain historical records; generate a new PDF to use localized structured date labels. Arbitrary legacy text is not parsed or translated automatically. Profile changes still require a current reviewed resume before assisted preparation.

Real employer submission was not performed. Lever contact-field assistance remains experimental; uploads, questions, legal consent, review and submission are manual. Docker and Windows/Linux installation paths were not verified in this release. Keyboard and responsive checks are regression coverage, not a full WCAG conformance certification.

The repository remains private. Public-release preparation and the previously deferred dependency alerts are outside this iteration.
