# v0.9.1 Reliability and usability fixes

This release corrects ten issues in assistant recovery, saved answers, application tracking and settings. It also includes the tracking-button alignment and local startup fixes reported after v0.9.0.

## Corrections

1. Selecting a resume checks equivalent job identities before creating another application. A conflict points to the existing application ID and leaves both records unchanged.
2. Expired manual and assistant answers are excluded from preparation. The profile marks them as needing an update, and approval requires editing and saving a new version.
3. Reopening the same assistant answer preserves manual edits, including after a failed save. Switching to another suggestion asks before replacing the review.
4. Natural-language search text and its open panel survive navigation and reload in the same tab. Signing out clears these drafts; failed browser storage is reported.
5. A profile revision removes unavailable experience selections and asks the person to select the current details explicitly. An edited answer is preserved.
6. Failed, interrupted and cancelled tasks are recovered alongside earlier successful suggestions. The outcome and possible quota use remain visible.
7. Failed history reads offer a retry before a new task; a concurrent-task conflict recovers progress and cancellation controls.
8. Replaying a preview after its task was removed returns an expired-preview response, rather than a successful response without a task or an automatic rerun.
9. Withdrawing permission refreshes automatic-summary settings; pausing summaries refreshes saved permissions.
10. Codex preflight requests official usage information. A reported exhausted limit blocks dispatch; missing usage information remains unknown.

The tracking action keeps its natural height and aligns with its selector. Mobile layouts keep a full-width action. Local launchers serialize startup and wait for an existing start to finish. Dependency preparation stays inside the launcher using the frozen lockfile.

## Upgrade

Create a verified backup, stop services, update the checkout and run `pnpm install --frozen-lockfile`, followed by `pnpm start`. There is no new migration after 0010. Existing profile data, searches, PDFs, connections and grants are retained. A restore continues to revoke grants and pause assistant automation as documented in the backup guide.

The project pins pnpm 11.10.0. An update notification does not require a pnpm upgrade. Interrupted launches may leave `data/launcher.lock`; confirm that the launcher and compiler have stopped before removing that file. See [local startup and recovery](../operations/local-setup.md).

## Verification and limits

Local checks completed before preparing the release candidate:

- 77 domain tests.
- 213 assistant tests and 23 native-probe/restore checks, using synthetic processes.
- 19 backup, restore and migration integration tests with disposable databases.
- 2 preparation integration scenarios, including concurrent attempts to select a resume for an equivalent job.
- TypeScript checks for packages and E2E code, and ESLint.
- Isolated production-browser checks of draft persistence, repeated review after failed save, expiry labels, obsolete selections, terminal-task recovery, failed history requests, duplicate-start recovery and synchronized settings. ES/EN widths: 360, 768, 1096 and 1440 CSS pixels, plus 720×450 and keyboard focus checks.

The complete isolated browser suite and GitHub CI must also finish successfully before publication.

All new assistant checks use synthetic provider responses. No additional account-backed Codex task is authorized or consumed for this release. Browser checks run against disposable databases, private ports and a separate production build; they verify that the live workspace remains unchanged.

Native AI support remains macOS with Codex CLI 0.160.0 and ChatGPT plan authentication. Claude remains deferred. These checks do not certify other native runtimes, every possible model output, screen-reader use or usability with new participants. The original connection evidence remains in [v0.9.0 validation](v0.9.0-validation.md).
